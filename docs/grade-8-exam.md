# Grades 6–8 JavaScript exam

Student page: `/exam`. Teacher results: `/admin/exams`, also linked from the teacher navigation. All learner-facing instructions and questions are Mongolian.

The exam contains 20 new multiple-choice questions (2 points each) and 6 new coding tasks (10 points each), for 100 points. Tasks cover the shared introductory JavaScript material for Grades 6–8: `let`, reassignment, arithmetic, `console.log`, comparisons, `if / else if / else`, `&&` and `||`. Questions and coding scenarios differ from the practice bank. Students have 35 minutes from the start of each attempt. They can retake only after an assigned teacher resets the attempt.

Only registered, active Grade 6, 7 or 8 profiles may start. An assigned teacher chooses **Код олгох** beside the student in `/admin/exams` and privately gives them the displayed code. The student enters their ID and code on `/exam`. Each code is valid for 30 minutes and admits one browser. To recover on another device, the teacher issues a replacement code. This revokes the previous browser and preserves the student’s saved answers and deadline. On rollout, students with an older exam session also need a code. An HttpOnly session resumes the same MongoDB attempt. Reloading or signing in again does not restart the server deadline. Writes require the saved revision; concurrent tabs cannot silently overwrite one another. Answers save after a short pause and every 30 seconds, with a separate recovery copy per tab. Reloading restores that tab’s draft. Other unsent drafts can be opened explicitly from the exam screen. At the deadline, only answers received by the server before the deadline are graded. Network failures remain visible and can be retried. Reconnects after the deadline cannot submit new answers.

Login allows 30 seconds and retries one temporary network or gateway failure. Server-side attempt creation is idempotent, so that retry resumes the same attempt and deadline. Saves and submissions retain their 15-second request limit and do not automatically replay a write with an uncertain result. Connection errors are shown in Mongolian; unexpected server errors log only an event and error name, without student answers or credentials.

During an active attempt, the server redirects other KodLab page requests from that browser to `/exam` and rejects other application APIs. The lesson progress API additionally blocks load/save for the student's ID, including a request without the exam cookie. Existing tabs receive a storage/focus/pageshow check to return to the exam. Submission or expiry releases the restriction. Cached content, cleared cookies, another browser/device/ID, other websites and other apps cannot be fully controlled by a normal website. Use a managed exam browser or supervised device policy when those restrictions are required. Full screen is offered; blur, hidden-tab and full-screen exit events are recorded with duplicate events within two seconds coalesced. These events are observations, not proof of cheating, and never automatically fail a student.

Coding is graded on the server using a restricted TypeScript AST interpreter. Student code is never passed to `eval`, a Node VM, a shell or a network-enabled runtime. Only primitive values, variable declarations/assignment, arithmetic/comparison/logical expressions, conditionals and `console.log` are supported. Code length, recursion depth, evaluated steps and output lines are bounded. Public examples can be run during the attempt; hidden cases and answer keys stay server-side. Coding points are proportional to hidden cases passed, rounded to whole points; requested syntax is also checked. Students receive a submission receipt; scores and saved responses are available only to teachers assigned to that student.

MongoDB collections are `exam_attempts` and `exam_sessions`; attempts are retained, while hashed session tokens expire after eight hours. Existing lesson progress is not modified. An assigned teacher can choose **Дахин өгөх** on a student row and confirm the named student. Reset atomically records the previous answers, code, status, score and reset actor/time in `previousAttempts`, then leaves the student ready to retake. The timer starts only when the student signs in again. The teacher can review earlier attempts using the attempt selector in the saved-work dialog.

Each reset increments an attempt generation. Sessions and writes are bound to that generation; old cookies, late saves/submissions and old browser draft backups cannot overwrite the retake. A student whose session is reset returns to the ID entry form after the next request. Legacy attempts without a generation are treated as generation zero. Only sessions redeemed with a teacher-issued code authorize access. Class groups, searching and exports show only students assigned to the authenticated teacher, using the existing class sidebar.

The original `javascript-8-2026-10-v1` exam ID is intentionally retained so expanding eligibility does not reset Grade 8 attempts, deadlines, history or recovery drafts. Teacher lists and class resets use the same supported grades (6, 7 and 8). Lesson access already permits active registered students, including all three grades; course progress remains keyed by course and student ID.

History is embedded in the exam document. Move it to a separate collection before a student needs 100 retakes for this same exam. A new exam with different content requires a new versioned exam ID.

For class-wide retakes, select a class in `/admin/exams` and choose **Ангид дахин өгөх эрх нээх**. The confirmation states the affected count and warns about active attempts. It includes all resettable students assigned to that teacher in the selected class, even if a search hides their rows. Unstarted and already-ready students remain unchanged. The server authorizes the entire selection before writing, then resets at most four attempts concurrently. Each target retains its confirmed generation, so a repeated request cannot reset a newer retake. The result reports successful, changed and failed targets separately; unexpected partial failures never claim the whole class succeeded. Existing row-by-row resets remain available.

Verification: question/task freshness and count checks, correct and incorrect grading, arbitrary-code rejection, malformed answer validation, real local MongoDB session/save/resume/deadline/concurrency checks, route and API restrictions, cross-teacher denial and submitted-attempt protection. Browser and deployment evidence is recorded separately in the task's private work folder.
